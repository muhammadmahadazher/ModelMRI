# Support

- Read the [documentation](https://muhammadmahadazher.github.io/ModelMRI/docs/)
  — installation, guides for each panel, and the HTTP API reference.
- Check [Troubleshooting](https://muhammadmahadazher.github.io/ModelMRI/docs/troubleshooting/)
  first. Most of it is written from failures that actually happened: stalled
  downloads, CPU fallback, gated repositories, SAEs that don't match the model.
- Search [existing issues](https://github.com/muhammadmahadazher/ModelMRI/issues).
- Open a [bug report](https://github.com/muhammadmahadazher/ModelMRI/issues/new?template=bug_report.yml)
  when you can describe what you ran and what you saw.
- Start a [feature request](https://github.com/muhammadmahadazher/ModelMRI/issues/new?template=feature_request.yml)
  for scoped ideas.

**Please don't file "the model says something wrong" as a ModelMRI bug.** That
is the model's output, and showing it to you honestly is the tool working. A
ModelMRI bug is when the *instrumentation* is wrong — attention attributed to
the wrong tokens, features from the wrong hook point, a panel describing a
generation that a different model produced.

For vulnerabilities, follow [SECURITY.md](SECURITY.md) and do not use a public
issue.
